## 1. 产品定位

### 1.1 一句话

**收纳屋** —— 面向家庭用户的 **移动端储物库存管理 H5（可安装 PWA）**：用彩色卡片一眼看清「家里还有多少」，并用「位置 + 数量 + 保质期 + 照片」把纸尿裤、生活用品、衣服等各类物品管起来。

### 1.2 核心痛点

| 痛点 | 产品如何解决 |
|------|-------------|
| 东西买多了堆着，不知道还剩多少 | 首页双列色块卡片，大数字展示存量 |
| 放哪了找不到 | 位置体系：房间 → 柜子/冰箱 → 层/盒 |
| 过期浪费 | 保质期字段 + 临期/过期提醒 |
| 录入麻烦 | 拍照上传、快速加减库存、扫条码（二期） |
| 多端/家人共享 | 账号登录 + 家庭空间（二期可开共享） |

### 1.3 与参考截图的关系

首页视觉与交互对标截图「我的存量」：

- 大标题 + 搜索框
- 双列圆角色块卡片
- 左上名称、右上 `···` 快捷菜单、左下超大数量
- **扩展点**：卡片可代表「物品 SKU」或「分类汇总」；本期默认 **每个卡片 = 一个库存物品（SKU）**，颜色跟分类绑定

## 2. 竞品 / 开源参考（GitHub）

| 项目 | 技术栈 | 可借鉴点 | 与我们的差异 |
|------|--------|----------|--------------|
| [sysadminsmedia/homebox](https://github.com/sysadminsmedia/homebox) | Go + Vue，自托管 | 位置层级、标签、图片、多用户 Group、CSV、搜索 | 偏「资产盘点」，弱「消耗品数量/保质期」；UI 偏后台 |
| [ZCX-Priv/E-Store](https://github.com/ZCX-Priv/E-Store) | Vue3 + Vite + PWA + IndexedDB | 网格/列表、分类色、低库存、vite-plugin-pwa | **无后端、无登录**，纯本地，不适合多端同步 |
| [Shadoukita/Listly](https://github.com/Shadoukita/Listly) | Vue3 + Flask + PWA | 位置库存、低库存阈值、家庭角色 | 偏购物清单/食谱；保质期未完成 |
| [JeffreyDissmann/stockroom](https://github.com/JeffreyDissmann/stockroom) | Laravel + Vue PWA | 房间/容器树、多图、活动日志、家庭 | 偏重，AI/搜索栈过重 |
| [BrandonKowalski/backstock](https://github.com/BrandonKowalski/backstock) | Go + Vue3 移动优先 | 多位置、加减库存、低库存、分类、全文搜索 | 功能精简，缺照片/保质期深度 |
| [calleft/StowAgent](https://github.com/calleft/StowAgent) | React H5 Demo | 拍照入库、找物体验 | Demo，无真实后端 |

### 2.1 设计结论（我们要做成什么样）

- **视觉**：学截图色块卡片（E-Store / 参考图），不做 HomeBox 那种桌面后台风  
- **数据能力**：学 HomeBox / Stockroom 的位置层级 + 图片  
- **消耗品能力**：学 Listly / Backstock 的数量、低库存、快速出入库  
- **架构**：必须前后端分离 + 登录（不选 E-Store 纯本地方案作主路径；PWA 离线作增强）

## 3. 用户与使用场景

### 3.1 角色

| 角色 | 说明 |
|------|------|
| 个人用户 | 注册登录，管理自己的库存（MVP） |
| 家庭成员 | 加入同一「家庭空间」，共享库存（V1.1） |
| 访客/未登录 | 仅可看登录/注册页 |

### 3.2 典型场景

1. **买完纸尿裤回家**：拍照 → 选分类「母婴」→ 填数量/位置/保质期 → 入库  
2. **换尿布用掉 1 包**：首页点卡片 `···` →「减少」或详情页一键 -1  
3. **找备用毛巾**：搜索「毛巾」或按「卫生间」位置筛选  
4. **换季衣服**：衣服类物品记尺码、季节标签、存放位置（衣柜/真空袋）  
5. **临期提醒**：打开 App，顶部看到「3 件 7 天内过期」

## 6. 交互与 H5 设计规范

### 6.1 设计原则

1. **一眼存量**：首页数量是第一视觉，信息层级 = 数量 > 名称 > 次要状态  
2. **拇指友好**：底部 Tab + 右下角 FAB「+」；卡片高度足够大，避免误触  
3. **少步骤**：常用操作用 `···` ActionSheet（±1、编辑、删除），不必每次进详情  
4. **状态可见**：临期角标、低库存角标、过期灰度  
5. **移动优先**：设计稿宽度 375；最大内容宽约 480，桌面居中留白

### 6.2 视觉方向（沿用参考图）

| Token | 建议 |
|-------|------|
| 页面底 | `#F5F5F7` 浅灰 |
| 标题 | 22–24px，加粗，近黑 |
| 搜索框 | 白底圆角 12，弱边框 |
| 卡片圆角 | 16–20 |
| 卡片文字 | 白 / 高对比 |
| 分类色板 | 预设 8–12 色（绿/酒红/蓝/橄榄/青/天蓝/棕/紫…） |
| 组件库 | **Vant 4**（Vue3 H5 成熟方案） |

### 6.3 关键页面线框说明

**首页**

```
┌─────────────────────────┐
│ 我的存量            筛选 │
│ ┌─────────────────────┐ │
│ │ 🔍 搜索物品/位置    │ │
│ └─────────────────────┘ │
│ ⚠ 临期 2 · 低库存 1     │  ← 可点进提醒
│ ┌──────┐ ┌──────┐      │
│ │名称 ···│ │名称 ···│      │
│ │      │ │      │      │
│ │ 468  │ │ 292  │      │
│ └──────┘ └──────┘      │
│ ┌──────┐ ┌──────┐      │
│ │ ...  │ │ ...  │      │
│ └──────┘ └──────┘      │
│                    [+]  │
├─────────────────────────┤
│ 存量  位置  提醒  我的   │
└─────────────────────────┘
```

**添加物品**

1. 选图（可选）→ 2. 名称/分类/数量 → 3. 位置/保质期/阈值 → 保存  
表单用 Vant Form；拍照入口放顶部大卡片。

**物品详情**

- 顶部大图 / 色块头图  
- 数量区：大数字 + `-` `+` 按钮 +「入库/出库」  
- 信息区：位置面包屑、保质期、分类标签  
- 底部：编辑、更多

### 6.4 关键状态

| 状态 | 表现 |
|------|------|
| 空库存列表 | 插画 +「添加物品」按钮 |
| 搜索无结果 | 「没有找到，试试别的关键词」 |
| 加载中 | 骨架屏（卡片灰块） |
| 上传中 | 进度条 / Toast |
| 网络错误 | 顶部错误条 + 重试 |
| 低库存 | 卡片右下角小角标或数量变琥珀 |
| 已过期 | 卡片半透明 +「已过期」角标 |

## 7. 领域模型（数据设计）

### 7.1 ER 关系（简化）

```
User 1───* Item
User 1───* Category
User 1───* Location
Location 1───* Location（parent_id，最多 2～3 级）
Category 1───* Item
Location 0..1───* Item
Item 1───* ItemImage
Item 1───* StockLog
```

> V1.1 引入 `Household` 后，Item/Category/Location 归属家庭，User 通过 Membership 关联。

### 7.2 核心表字段

**users**  
`id, username(账号唯一), password_hash, nickname, avatar_url, created_at, updated_at`

**categories**  
`id, user_id, name, color(#RRGGBB), icon, sort, is_system, created_at`

**locations**  
`id, user_id, parent_id, name, sort, created_at`

**items**  
`id, user_id, category_id, location_id, name, quantity(decimal), unit,  
 low_stock_threshold, expire_at(date nullable), brand, spec, season,  
 remark, cover_url, status(active/archived), created_at, updated_at`

**item_images**  
`id, item_id, url, sort, created_at`

**stock_logs**  
`id, item_id, user_id, delta, quantity_after, reason(use/purchase/adjust/waste), note, created_at`

### 7.3 业务规则

1. `quantity` 不允许为负；减到 0 仍保留卡片（方便补货），可手动归档  
2. 每次数量变更必须写 `stock_logs`  
3. 删除物品：软删除（`status=archived`）或回收站  
4. 分类色变更后，首页卡片色即时跟随  
5. 无 `expire_at` 的物品不进入临期列表

## 8. 技术架构

### 8.1 推荐技术栈（已定方向）

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | **Vue 3 + Vite + TypeScript** | 你指定；生态成熟 |
| UI | **Vant 4** | H5 组件全、移动体验好 |
| 状态 | **Pinia** | 官方推荐 |
| 路由 | **Vue Router 4** | — |
| HTTP | **Axios** | 拦截器挂 Token |
| PWA | **vite-plugin-pwa** | 你指定 |
| 后端 | **NestJS + Prisma** | TS 全栈一致；模块清晰；鉴权/上传成熟 |
| DB | **SQLite**（本地开发）→ 后期可切 PostgreSQL | Prisma 切换成本低 |
| 鉴权 | **JWT**（access 2h + refresh 7d）；登录字段为 **账号+密码** | 前后端分离标准做法 |
| 文件 | 本地 `uploads/`（Docker volume）；后期可换 OSS | MVP 零成本 |
| 部署 | Docker Compose：`web` + `api` + `db` | 一键起 |

备选后端（若更熟 Python）：**FastAPI + SQLAlchemy**，接口契约保持不变。

### 8.2 仓库结构（Monorepo 建议）

```
storage-h5/
├── apps/
│   ├── web/                 # Vue3 H5
│   └── api/                 # NestJS
├── docs/
│   └── 产品设计方案.md
├── docker-compose.yml
└── README.md
```

### 8.3 前端模块

```
src/
├── views/          # 页面：Home, Locations, Alerts, Profile, Auth, Item*
├── components/     # StockCard, SearchBar, QtyStepper, ImageUploader...
├── stores/         # user, item, category, location
├── api/            # 接口封装
├── composables/    # useExpire, usePwaInstall...
├── styles/         # 变量、卡片色板
└── router/
```

### 8.4 后端模块

```
auth / users / categories / locations / items / uploads / alerts(统计查询)
```

### 8.5 API 一览（REST，前缀 `/api/v1`）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/auth/register` | 注册（username + password + nickname?） |
| POST | `/auth/login` | 登录（username + password） |
| POST | `/auth/refresh` | 刷新 Token |
| GET | `/me` | 当前用户 |
| GET/POST | `/categories` | 分类列表/新建 |
| PATCH/DELETE | `/categories/:id` | 改/删 |
| GET/POST | `/locations` | 位置树/新建 |
| PATCH/DELETE | `/locations/:id` | 改/删 |
| GET | `/items` | 列表：`q, categoryId, locationId, expire, lowStock, page` |
| POST | `/items` | 新建 |
| GET/PATCH/DELETE | `/items/:id` | 详情/改/删 |
| POST | `/items/:id/stock` | `{ delta, reason, note }` 变更数量 |
| GET | `/items/:id/logs` | 流水 |
| POST | `/uploads` | multipart 图片，返回 url |
| GET | `/alerts/summary` | 临期/过期/低库存数量 |

统一响应：

```json
{ "code": 0, "message": "ok", "data": {} }
```

## 13. 风险与取舍

| 点 | 决策 |
|----|------|
| 家庭共享是否 MVP？ | **否**，先做个人账号，表结构预留 `household_id` |
